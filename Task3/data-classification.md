# Задание 3. Классификация данных и оценка защиты

## 1. Контекст

Компания «Медикаменте» обрабатывает персональные, медицинские, платёжные и коммерческие данные. Для соответствия требованиям законодательства РФ (152-ФЗ, 115-ФЗ, 323-ФЗ «Об основах охраны здоровья граждан», требования к врачебной тайне) необходимо классифицировать данные, обосновать необходимость защиты каждого класса и выбрать инструменты защиты.

Акцент данного задания — на обеспечении **шифрования данных at rest** (при хранении) и **in transit** (во время передачи), а также автоматизированном контроле и реестре средств защиты.

## 2. Модель угроз (кратко)

| Угроза | Последствие |
|---|---|
| Утечка ПДн / PHI пациентов | Репутационный ущерб, штрафы Роскомнадзора, исковые требования |
| Несанкционированный доступ сотрудников к медицинским картам | Нарушение врачебной тайны, уголовная ответственность |
| Перехват данных при передаче между системами | Утечка конфиденциальных данных, компрометация API |
| Кража физических носителей / резервных копий | Полная компрометация данных без шифрования |
| Внутренний злоумышленник с доступом к БД | Просмотр и кража данных, необходимость аудита и маскирования |

## 4. Принципы шифрования

### At rest

| Уровень | Механизм | Применение |
|---|---|---|
| Инфраструктурный | Шифрование дисков / томов (LUKS, BitLocker, EBS/S3 encryption) | Все серверы и хранилища |
| База данных | TDE (Transparent Data Encryption) в PostgreSQL | Операционные БД с ПДн и PHI |
| Уровень столбцов | Шифрование отдельных полей (SSN, диагнозы, паспортные данные) | Особо чувствительные атрибуты |
| Файловое хранилище | SSE-S3 / SSE-KMS (AES-256) | S3 / MinIO для документов и сканов |
| Резервные копии | Шифрование бэкапов на уровне файловой системы или СХД | Все backup-ы |
| Секреты | Хранение в Vault с шифрованием | API-ключи, пароли, сертификаты |

### In transit

| Уровень | Механизм | Применение |
|---|---|---|
| Внешний трафик | TLS 1.2+ (предпочтительно 1.3), HSTS | Портал пациентов, мобильное приложение |
| Внутренний трафик | mTLS между микросервисами | Сервис записи ↔ CRM ↔ Notification Service |
| API интеграции | TLS + OAuth 2.0 / OIDC + подпись запросов | Интеграция с лабораторией |
| Управление ключами | HashiCorp Vault / AWS KMS / Yandex KMS | Ротация сертификатов и ключей шифрования |

## 5. Автоматизированный контроль

Для обеспечения непрерывного контроля за данными и соблюдения политик безопасности необходимо внедрить следующие средства автоматизации:

| Категория контроля | Инструмент | Назначение |
|---|---|---|
| **Управление доступом** | Keycloak + Active Directory | Централизованная аутентификация, RBAC/ABAC, MFA, аудит входов |
| **Политики доступа к данным** | Apache Ranger | Тегирование данных, маскирование столбцов, фильтрация строк, аудит обращений |
| **Каталог данных и тегирование** | Apache Atlas | Классификация данных, lineage, метки чувствительности |
| **Управление секретами и ключами** | HashiCorp Vault / KMS | Хранение ключей шифрования, сертификатов, API-ключей, их ротация |
| **Мониторинг и SIEM** | Elastic SIEM / Wazuh | Сбор событий безопасности, корреляция, алертинг на аномалии |
| **DLP** | DLP-система (встроенная или отдельная) | Предотвращение утечек конфиденциальных данных по каналам коммуникаций |
| **Сканирование конфигураций** | OpenSCAP / Terraform Sentinel | Проверка соответствия инфраструктуры политикам шифрования и безопасности |
| **Сканирование уязвимостей** | Trivy / Nessus / Dependency-Check | Поиск уязвимостей в образах, зависимостях и инфраструктуре |
| **Аудит SQL-запросов** | pgaudit / Database Activity Monitoring | Логирование обращений к чувствительным таблицам и столбцам |
| **Политики в CI/CD** | GitLab CI / GitHub Actions + Policy-as-Code | Автоматическая проверка релизов на работу с тегированными данными |

## 7. Соответствие целевой архитектуре

Диаграмма контекста C4 (Task2) включает все системы, в которых хранятся перечисленные классы данных:

- **Портал пациента**, **CRM** — ПДн и PHI пациентов.
- **Сервис записи на приём** — данные о записях и слотах.
- **Сервис уведомлений** — контактные данные для email/SMS/push.
- **1С:Бухгалтерия**, **ККМ** — платёжные данные.
- **1С:Торговля и склад** — коммерческие данные по ТМЦ.
- **Data Ingestion & Anonymization**, **Data Lake** — обезличенные аналитические данные.
- **IAM / Keycloak + AD**, **HashiCorp Vault** — учётные данные и секреты.

## 8. Рекомендации

1. **Внедрить единую политику шифрования** для всех систем, обрабатывающих ПДн и PHI.
2. **Использовать Vault** как единый источник управления ключами и сертификатами.
3. **Настроить mTLS** между всеми микросервисами целевой архитектуры.
4. **Обеспечить обезличивание** перед загрузкой данных в Data Lake.
5. **Включить аудит** всех обращений к зашифрованным данным в SIEM.
6. **Регулярно ротировать ключи** шифрования и сертификаты TLS.
7. **Внедрить Policy-as-Code** в CI/CD для автоматической проверки релизов на работу с тегированными данными.
