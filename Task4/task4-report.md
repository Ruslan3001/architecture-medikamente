# Задание 4. Оценка узких мест при миграции

## 1. Анализ ситуации

Компания «Медикаменте» планирует миграцию с устаревшего ландшафта (Excel, 1С в файловом режиме, общие сетевые папки, единый физический сервер) на современную целевую архитектуру MVP: портал пациента, портал ресепшена, CRM, сервис записи, платёжный шлюз, интеграция с лабораторией, Data Lake и BI.

Ключевые компоненты, затронутые миграцией:
- **Базы данных** — перенос пациентских, платёжных и учётных данных из Excel/1С в PostgreSQL / S3.
- **Коммуникационные каналы** — замена OLE/общих папок на API, mTLS, OAuth 2.0.
- **Серверное оборудование** — выход за пределы одного физического сервера, переход к отказоустойчивой инфраструктуре.
- **Бизнес-логика** — декомпозиция монолитных процессов 1С в микросервисы.

## 2. Диаграмма Исикавы

Диаграмма «Рыбья кость» построена в файле `ishikawa-migration.drawio`. Она включает пять классических категорий, влияющих на риски и узкие места миграции:

- **Персонал**
- **Процессы**
- **Инфраструктура**
- **Программное обеспечение**
- **Интеграция**

## 3. Категории и возможные проблемы

| Категория | Проблема | Влияние на миграцию |
|---|---|---|
| **Персонал** | Нехватка IT-специалистов (3 человека в отделе) | Недостаток ресурсов на проектирование, разработку и поддержку новой архитектуры |
| **Персонал** | Отсутствие опыта работы с Kubernetes / микросервисами | Риск ошибок при эксплуатации, замедление внедрения, необходимость обучения |
| **Персонал** | Сопротивление изменениям со стороны сотрудников | Снижение скорости adoption новых процессов, риск возврата к Excel |
| **Процессы** | Ручные процессы в Excel не автоматизированы | Высокая трудоёмкость переноса, риск человеческих ошибок |
| **Процессы** | Отсутствие регламентов по работе с конфиденциальными данными | Регуляторные риски (152-ФЗ, врачебная тайна), утечки PII/PHI |
| **Процессы** | Дублирование данных в нескольких системах | Неконсистентность, сложность синхронизации при миграции |
| **Процессы** | Отсутствие плана отката (rollback) | При сбое в продакшене невозможно быстро восстановить работу бизнеса |
| **Инфраструктура** | Один физический сервер в офисе — единая точка отказа | Высокий риск простоя, отсутствие масштабируемости |
| **Инфраструктура** | Отсутствие резервного копирования и DR | Утрата данных при сбое, невозможность восстановления |
| **Инфраструктура** | Необходимость масштабирования при пятикратном росте | Текущая инфраструктура не выдержит увеличение нагрузки |
| **Программное обеспечение** | 1С в файловом режиме, ограниченная масштабируемость | Блокирует рост количества пользователей и транзакций |
| **Программное обеспечение** | Монолитная архитектура затрудняет поэтапную миграцию | Высокий риск big-bang перехода, сложность тестирования |
| **Программное обеспечение** | Отсутствие единой модели данных (MDM) | Дублирование, рассогласование сущностей «пациент», «услуга», «оплата» |
| **Интеграция** | Отсутствие API для интеграции с лабораторией | Невозможно реализовать целевой сценарий получения результатов анализов |
| **Интеграция** | Legacy-интеграции через OLE и общие папки | Ненадёжные, небезопасные и непрозрачные точки обмена данными |
| **Интеграция** | Несовместимость форматов данных между системами | Затраты на трансформацию данных, ошибки при миграции |

## 4. Рекомендации по устранению узких мест

| Приоритет | Мера | Обоснование | Категория |
|---|---|---|---|
| **Высокий** | Развернуть резервное копирование и DR до начала миграции | Минимизация риска утраты данных и простоя при сбоях | Инфраструктура |
| **Высокий** | Внедрить единую IAM (Keycloak + AD), RBAC/ABAC и аудит доступа | Соответствие 152-ФЗ и требованиям безопасности PHI | Процессы / Персонал |
| **Высокий** | Подготовить план отката (rollback) и пилотную миграцию на небольшой группе данных | Снижение риска сбоев в продакшене | Процессы |
| **Высокий** | Обучить команду работе с Kubernetes, CI/CD и observability | Компетенции критичны для сопровождения целевой архитектуры | Персонал |
| **Средний** | Выделить API Gateway и сформировать контракты интеграции с лабораторией | Необходимо для целевого MVP | Интеграция |
| **Средний** | Построить единую модель данных (MDM) и карту миграции данных | Устраняет дублирование и рассогласование | Программное обеспечение |
| **Средний** | Разделить миграцию на этапы: сначала запись и CRM, затем платежи и лаборатория | Снижает сложность big-bang | Процессы / Программное обеспечение |
| **Средний** | Внедрить мониторинг, логирование и алертинг до запуска MVP | Раннее обнаружение проблем производительности | Инфраструктура |
| **Низкий** | Оптимизировать или заменить 1С файлового режима на клиент-серверный / API-интеграцию | Долгосрочная масштабируемость | Программное обеспечение |
| **Низкий** | Провести change management и обучение бизнес-пользователей | Повышение adoption и снижение сопротивления | Персонал |

## 5. Выводы

Основные узкие места миграции сосредоточены в трёх областях:
1. **Инфраструктура** — отсутствие отказоустойчивости и масштабируемости.
2. **Процессы и данные** — ручные операции, дублирование, отсутствие регламентов.
3. **Интеграции** — устаревшие механизмы обмена данными и отсутствие API.

Для успешной миграции на MVP критично начать с обеспечения базовой инфраструктурной надёжности (backup/DR), безопасности доступа и постепенного перевода процессов с минимизацией big-bang рисков.
